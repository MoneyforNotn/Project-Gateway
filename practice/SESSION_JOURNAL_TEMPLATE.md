# Session Journal Template

[Learning path](LEARNING_PATH.md) · [Simple session](LEARNING_PATH.md#a-simple-session) · [Methodology](../research/METHODOLOGY.md) · [Glossary](../research/GLOSSARY.md)

Keep a short record that distinguishes what happened from what it might mean. Most entries should take about three minutes across the session and next-day check. Use the optional sections only when relevant.

Copy the blocks below into a private note or notebook. A local Markdown file works; no app, account, or public upload is needed. Do not put personal health information or other people's private details into a public repository or issue.

**Use the same measures throughout.** The learning path defaults to tension before/after and one daily outcome, such as completing a preselected 15-minute task by day's end. Choose and define an alternative before starting, then keep that definition stable. These personal ratings are not clinical scores.

- **Tension:** 0 = none; 10 = as tense as I can imagine. Change = after − before; negative means less reported tension.
- **Expected helpfulness:** 0 = no help expected; 10 = very helpful. Record before the session.
- **Sleep quality:** 0 = very poor; 10 = very restful. Record after waking.
- **Session status:** completed / shortened / stopped / missed. Record the actual duration; a missed session still gets a brief entry.

## Setup and baseline

Copy once. Take 3–7 days of baseline records before the practice route; see [preparation](LEARNING_PATH.md#preparation-before-week-1). The reading-only route can use the [claim card](#reading-only-claim-card) instead.

```text
Question I am exploring:
Planned session days and approximate time:
Primary immediate outcome: tension, or this defined alternative:
Daily outcome and when I will check it:
What counts as a useful change for me:
Personal stop rule:
Baseline dates:

One row per baseline day; keep the usual routine.
Date | Tension at planned session time | Sleep quality | Daily outcome | Unusual context
     |                                 |               |               |
```

Continue the daily-outcome record on days without sessions. Do not fill in a missing rating from memory later; mark it missing.

## Session entry

Copy for each planned session. If missed, fill in the date, status, and reason only. Keep original entries; label later additions with their date and time.

```text
SESSION ID / WEEK:
Date and start time:
Condition: quiet rest / ordinary audio / named target audio / imagery / other
Audio title or file, if used:
Planned attention period / actual attention period (minutes):
Status: completed / shortened / stopped / missed
Reason for change or missed session:

BEFORE
Tension (0–10):
Expected helpfulness (0–10):
Sleep quality after last waking (0–10):
Relevant context or routine change (one line):

AFTER
Tension (0–10):
Tension change (after − before):
Direct observations (one or two sentences; “nothing notable” is fine):
Possible interpretation, kept separate:
Another plausible explanation, if any:
Any discomfort or unwanted effect, including none:
One ordinary action, if useful, and when I will check it:

NEXT-DAY CHECK — date/time:
Sleep quality (0–10):
Chosen daily outcome (same definition as baseline):
Any lingering benefit, discomfort, or effect on routine:
Did the action happen, and what was observed?
```

**Observation:** “My hands tingled; I pictured a blue doorway; I lost track of time.”<br>
**Interpretation:** “Perhaps attention, posture, expectation, or sleep onset contributed.”

Record an impression of a place or event as an experience. A claim that it matches an external fact belongs in a separate record made before checking that fact.

### Optional detail

Add only what helps answer the question. Do not search for a sensation to fill every field.

```text
Body sensations / sound / visual imagery:
Emotion and time sense:
Sense of body location or ownership:
Sleep-onset signs or dreamlike content:
Optional mood or focus rating: define endpoints and use them consistently.
```

## Pre-feedback record

Use only for an externally checkable claim or the optional [Week 5 demonstration](LEARNING_PATH.md#optional-concealed-target-demonstration). The full protocol is in the learning path; this block does not replace randomization, blinding, or independent judging. Do not use it to guide high-stakes decisions.

Keep the original report unchanged. Save a dated copy before anyone reveals the answer; a timestamp alone does not demonstrate that a record was never edited. Label all later additions and keep them outside the original.

```text
TRIAL CODE:
Report date/time:
Exact description or prediction / drawing location:
Confidence (0–100%, optional; not the scoring rule):
Who had access to the target or answer at this point?
Original copy location and who received it before feedback:
Report locked at:

JUDGE — complete and save before feedback
Judge ID:
Candidate labels and display order:
One selected best-match label:
Judgment locked at:
Was the judge blind to the target key? Any possible cue?

AFTER ALL REPORTS AND JUDGMENTS ARE LOCKED
Feedback date/time:
Target key and saved label-to-image mapping location:
True target label:
Predeclared score: 1 if chosen label = target label; otherwise 0
Score:
Protocol deviation / possible leakage / missing record, including none:
Scorable or compromised, with reason (retain either way):
Later interpretation — keep outside the original report:
```

## Weekly audit

Allow about ten minutes. A summary should include the awkward entries and missing data as well as the memorable ones. Compare like conditions and keep the outcome definitions fixed.

```text
Week / dates / route:
Planned sessions:
Completed / shortened / stopped / missed sessions:
Missing next-day checks:

For each condition, list every tension change and the number of observations:
Condition | Changes | Number | Average change | Next-day pattern / discomfort
          |         |        |                |

Chosen daily outcome: this week's record versus baseline:
Any change in schedule, sleep, or other context:
Did expected helpfulness track the result?
Did a dramatic experience produce anything useful the next day?
Unwanted effects or reasons to pause:
Action completed and result, including failures:
What can these records support? What can they not distinguish?
Next step: stop / continue / shorten / repeat one defined comparison
Next review date:
```

For the optional concealed-target exercise, add **trials planned / completed / scorable / compromised**, all individual scores, and the original scoring rule. Record misses and ambiguous reports as faithfully as hits. Do not turn a broad impression into a specific prediction after feedback.

For the final [Week 6 audit](LEARNING_PATH.md#week-6-integration-and-audit), include the baseline, adherence, expectancy, next-day outcomes, and all adverse effects in the decision. A before/after change or a preferred audio condition does not establish its cause.

## Reading-only claim card

Copy once per week; no session or personal disclosure is needed.

```text
Week / topic:
Claim in one sentence:
Source and exact section or page:
What was reported or measured?
What explanation is being proposed?
What additional observation would distinguish it from an alternative?
Main limitation or unresolved question:
What I would revise after reading:
```
